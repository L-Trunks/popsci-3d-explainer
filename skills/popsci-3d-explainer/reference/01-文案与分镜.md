# 01 · 文案与分镜（scenes.py）

## 单一事实源

口播和画面写在**同一个文件**里（`scenes.py`），稿 markdown 由它反生成。
不是「先写文章再切分镜」——那样会割裂，画面永远在追文字。

```
scenes.py  ──gen_gao.py──>  稿.md  ──grid_script.py──>  稿格子（一段一格）
    │                          ↑
    └──────check_scenes.py 逐字比对（CHECK_OK 才准渲）
```

⛔ 改了 `scenes.py` 就必须重跑 `gen_gao.py`，否则 `check_scenes.py` 会在渲染前一刻报「分镜和稿不一致」。

---

## 结构

```python
P("p03", [
    ("这是第一块的口播。", {"seg": "S11a"}),
    ("但问题来了，这是第二块。", {"seg": "S12a"}),
    ("这里放一张卡片。", {"card": C_RAM}),
])
```

- **一段** = 一条 wav = 一次 TTS = 一次对齐 = 一格「稿」+ 一格「段」
- **一块** = 一个镜头 = 一格「画」
- `P()` 自动给每块算 `at`（前 4 个字，用来在口播里定位）和 `off`（字符偏移）

画面三选一：

| 写法 | 是什么 |
|---|---|
| `{"seg": "S11a"}` | Blender 镜头。函数名 `S11`，段名 `S11a`（尾字母是切片名，一镜一段） |
| `{"card": {...}}` | `cards.py` / `cards2.py` 出的深色 PNG |
| `{"real": "bench"}` | 实测录屏，要有同名生成器 `bench.py` |

### 硬约束

- ⛔ 块的**前 4 个字**里不要放 `{{}}` 或 `*`（`at` 取前 4 字）
- ⛔ 同一个 `seg` / `real` **不许出现两次**。重复会让后一块覆盖前一块的 beats，那一镜只渲一小段
- ⛔ 一个 `seg` 只对应一个块
- 一段 **150~620 字**。超过 620 字的段，TTS 容易整段复读（见 `02-配音与对齐.md`）

### ⛔⛔ 第一段：观众必须在 20 秒内知道这片在讲什么

这条没有任何自动闸门能替你看，而它是**最贵的一种错**——发现的时候片子已经渲完了。

《显卡》v4 的开场块序是：

```
① 546 亿次乘加  ②「干这个活的是一块显卡」 ③ 卖二十多万
④ 插不上显示器  ⑤「凭什么这么贵」        …  ⑨「显卡到底是干什么的？」
```

用户的原话是「开头我都不知道你在讲什么」。病因不在文笔，在**次序**：

> **反常需要一个常态当背景板。**
> 「一块插不上显示器的显卡」之所以是钩子，前提是观众脑子里已经有
> 「显卡 = 让屏幕出画面的东西」。小白没有这个常识，
> 你把反常摆在常识前面，他拿到的不是悬念，是困惑。

而「显卡到底是干什么的」排在第 ⑨ 块、约 40 秒之后。前 40 秒讲的是一块
**观众认知里根本不存在的东西**（数据中心加速卡）。

判据（写完第一段自己过一遍）：

1. **20 秒判据**：念到第 20 秒时，一个没看过这题材的人能不能用一句话说出
   「这片在讲 X」？说不出就重排，不是重写。
2. **反常识钩子的前置条件**：你要翻的那个常识，观众**已经有**吗？
   - 有（冰箱制冷、洗衣机洗衣）→ 可以开场就翻。
   - 没有（显卡、光刻机、HBM）→ **先用一句话给常态，再翻**；
     或者干脆不翻，改用大数字换算开场。
3. 冷开场（日期+地点+人物+反常事件）只适用于**有「那一天」的题材**。
   一台机器没有「那一天」，硬套出来的就是一段没有主语的悬念。

⛔ 这一条和「知识的诅咒」是同一件事的两面：你已经知道显卡是什么了，
所以你觉得第 ⑨ 块才回答「它是干什么的」很自然——观众不是。

## 字数与时长

```
时长 ≈ 字数 ÷ 语速 × 60
```

语速取决于平台口径：**短视频平台约 320 字/分**，**长视频平台约 375 字/分**（我们两部片实测后的定档）。
`grid_script.py` 用 `config.speech_rate` 估，默认 323。

一块 = 一条字幕的量级：**≤16 个字**（1920 画布、60 号楷体、单行最宽 1000 px）。
写的时候按标点把长句切成 2~5 块。

## 读音覆盖 `{{显示|读音}}`

只改读法、不改显示。字幕、稿、`check_scenes` 的比对用**显示侧**，TTS 用**读音侧**。

```
{{2013|二零一三}}     ← 不写的话「2」会被读成「两」
{{重庆|虫庆}}         ← 多音字
{{CoWoS|COWOS}}       ← 见下面「英文怎么写」
{{，|。}}             ← 只换停顿语气，显示串一个字没动
```

⛔⛔ **只改读音侧时，显示串一个字都没变，但 wav 变了。** 不重新对齐字幕会整段错位。
`chain.audio()` 的 stale 判据因此要**同时**比三样：显示串、读音串、wav 时长。

### 英文怎么写：直接写英文

三轮实测 36 条 + whisper 回读，结论和直觉相反——**汉字转写才是「哑巴英语」的来源**：

| 写法 | 听到的 |
|---|---|
| `四零七零踢` | 4070**T** ✗ |
| `4070 Ti` | 4070Ti ✓ |
| `扣沃斯` | 扣卧师 ✗ |
| `CoWoS` 原样 | **Code WOS** ✗ |
| `COWOS`（全大写） | COWOS ✓ |
| `HBM` `DRAM` `RAM` `AMD` `AI` 原样 | 全部正确 ✓ |
| `1T` / `1 T` / `一 T` | 一律 **ET** ✗ |
| `1TB` | 1TB ✓ |
| `DDR5` 在「量产 DDR5」里 | **滴滴阿瓦** ✗ |
| `DDR 5`（带空格） | DDR5 ✓ |

所以：**英文一律直接写英文**，只给上面这种被念坏的少数几个加覆盖。
`check_read.py` 里有一道英文回读闸（读的那侧出现过、听的那侧没有的就报）。

#### ⛔⛔ 上面这张表只证明「没念丢」，证明不了「念得对」

`4070 Ti` 那一行打的 ✓ 是**转写**意义上的 ✓：whisper 听到什么都写回 `Ti`。
可「Ti」有两种念法——按字母念 **T-I**，和按中文念 **钛**。
两种念法回读出来是同一个字符串，**这道闸门在结构上就看不见这个区别**。
《显卡》v4 全片 3 处 `4070 Ti` 被按字母念了，闸门全绿，用户一听就听出来。

推论，每一条都要当真：
- 回读闸只能抓「漏读 / 多读 / 整段复读」，**抓不了读法**。读法只有人耳能验。
- 片子自己在 `scenes.py` 头部写的读音覆盖表，和本文件这张通用表**会打架**
  （v4 的表写着 `Ti=钛`，本表写着 `4070 Ti` 直接写）。打架时没有任何一步会报错，
  谁都不生效——正文里一个 `{{Ti|钛}}` 都没有。
- 所以：**读音覆盖表不能只写在 docstring 里**。见下面「表要能被扫」。

#### 表要能被扫

把覆盖表从注释挪成数据，再加一道 lint：

```python
READ_FIX = {"Ti": "钛", "薄": "báo", "长": "zhǎng"}   # ← 数据，不是注释

def lint_read_fix(scenes):
    """表里有的词，正文里必须套 {{}}；裸着出现就报。"""
    bad = []
    for s in scenes:
        nar = s["narration"]
        for w in READ_FIX:
            # 去掉已经套好的，剩下的还有就是漏网的
            left = re.sub(r"\{\{%s\|[^}]*\}\}" % re.escape(w), "", nar)
            if w in left:
                bad.append((s["id"], w))
    return bad
```

闸门放在 `check_scenes.py` 里，和「稿 ≡ 分镜逐字」同一道。
**表里加了词却没扫正文，等于没加。**

## 稿格子与 lint

```bash
python grid_script.py              # 看每段的字数 / 估时长 / 盖章状态
python grid_script.py --过 p03 "为什么这段可以过"
python grid_script.py --lint       # 机器可查的硬指标
```

指纹 = md5(该段口播)。**改一个字，那一格的章自动失效。**

`--lint` 查六类：

| 项 | 判据 |
|---|---|
| AI 味 | 行末冒号、「答案是：」、书面引号、「首先/其次/第一步」、「值得注意的是/总之/综上」、「99%」、模糊量词 |
| 气口过长 | 任意两个标点之间 >20 字（念着憋；>16 字字幕要断行） |
| 问句过多 | 一段 >3 个「？」 |
| 「我」过多 | 一段 >3 次（转述型科普里「我」≈0，见 skill `pov-it-and-you`） |
| 段过长 | >620 字 |
| **术语首现段** | 每个阻塞性名词第一次出现在哪一段 |

⛔ **术语首现段是最值钱的一条**：真栽过一次——某个词首现在第 2 段，解释却在十五分钟后的第 8 段。
修法不是在首现处补定义（补了就是 AI 味），而是**把那句话改成不需要这个词的说法**，
把这个词让给它真正该出场的那一段。

---

## AI 味怎么去

lint 只能抓形式。内容上的三条：

1. **名词解释不要写成「X 说的是 Y」**——那就是 AI 味。要么用一个动作把它演出来
   （「让铜面直接贴铜面，中间什么都不垫，这叫混合键合」），要么**干脆别引入这个术语**。
2. **名字后置**：先用两三句动作描述把观众带到能「看见」的地步，再补名字。名字是奖励不是前提。
3. **评价不用形容词**：不写「这个设计非常巧妙」，写「这不是 A，这是 B」。

细则在 skill `name-after-show`、`one-object-one-analogy`。

## 数据出处表

手写 `数据出处.md`，**每个数字一条**：算法、或者链接、或者「机构估」的口径说明。

- ⛔ 数字要**自查数量级**：反过来算一遍。真栽过「3 万亿 ÷ 3 万 = 5000 万倍」（实为 1 亿倍）。
- ⛔ 「据统计」「科学家发现」这种无主语的说法**不要用**——要么补机构和年份，要么删。
- ⛔ 用户凭印象给的说法，**和出处冲突时按出处写**，并在交付说明里点明这一处不一致。
  （真发生过两次：一次方向正好相反，一次原文明确否定了那个猜测。）

片尾出处卡的写法见 `templates/scenes.py` 的 `TAIL_CARDS`。**别放长链接**，观众记不住也点不了。

## 卡片什么时候用

**能用建模就别用卡片。** 纯文本画面占全片的比例是硬指标：
第一版 180 秒 / 18.6% 被判「像 PPT」，改到 **53 秒 / 5.0%** 才过。

卡片只留给：大数字、对照表、片尾出处署名。
「三个并排的数字」「一条时间轴」「一张份额饼图」这类**全部改成会长高的 3D 图表**
（`bl_charts.py`），三条纪律：

- ⛔ 名字刻在柱体/圆盘**自己身上**，跟着它一起动，不飘在旁边
- ⛔ 贴在会亮起来的物体上的字一律**深色不发光**（白字在亮面上看不清）
- ⛔ 数值跟着柱子长出来，不是一开始就杵在那
