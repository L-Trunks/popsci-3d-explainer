# 05 · 混音与 BGM

## 两条总原则

**① 改音色的活，能放进最后一次混音的就别放进素材层。**
回去改 `make.py voice()` 会连锁：每轮从 tts_raw 重建 → 重插停顿 → 重对齐 → 重出 beats →
**所有镜头的帧数全变**，几小时渲染作废。为一段低频不值。

**② 主观说法要先转成可测量的判据再动手。** 「中间平淡」「人声不够大」「有呜呜声」
这三条反馈，每一条先量、量完往往推翻直觉（见下）。

---

## 选曲：量整首，不是量中间 30 秒

```bash
python bgm.py scan          # 扫候选，按「能量 + 起音 − 过量次低频」打分 → work/bgm/scan.json
python bgm.py prof 80       # 量整首：lull / iqr / lvl / midr → work/bgm/prof.json
python bgm.py mix 1355      # 按 config.bgm.pick 拼混音 → work/film/bgm_mix.mp3
```

### `scan` 的打分

能量 + 起音强度 + 中频撑得住，惩罚「白噪」（spectral flatness）和「整首泡在次低频里」。
`lowr ≥ 0.62` 的直接不要。

⛔ `lowr`（150 Hz 以下能量占比）这一项是被「呜呜」逼出来的：
成片人声间隙里 30–120 Hz 比语音带高 6.6 dB，而一批史诗曲有 **37.4% 的能量压在 80 Hz 以下**。

### ⛔⛔ `prof` 才是决定性的：打分只听中间 30 秒，判不出「这首中间有一分钟几乎没声」

量**整首**，每 10 秒一格，只量 **200–2000 Hz**（史诗管弦的弦 / 铜管 / 合唱都在这一带，
「宏大」是这一带撑出来的，不是低频鼓垫）。三个指标：

| 指标 | 含义 | 要什么 |
|---|---|---|
| `lull` | 低于本曲中位 3.5 dB 的格子占比 | **≈0**（有没有塌下去的段落） |
| `iqr` | 四分位距 | 小（整首平不平稳） |
| `lvl` | 200–2k 的中位 | 高（撑不撑得住） |

实测那次「中间比较平淡」的反馈，量出来是三首具体的曲子：

| 曲子 | lull | iqr | lvl | 病 |
|---|---|---|---|---|
| A | **0.29** | 5.6 | 24.5 | 其中整整一分钟掉到 1.5 dB = **等于没声** |
| B | 0.18 | 2.0 | 24.0 | 次之 |
| C | 0.00 | 1.8 | **22.4（最低）** | 没塌段，但三分钟一直不来劲 |

换掉之后：**极差 26.1 → 8.6 dB，塌段格子十几个 → 2 个，整体中频 +1.2 dB。**

### 排曲单

按「lull≈0 + iqr 小 + lvl 高」挑，**把最响的几首放进中段**，开场和结尾各留一首标志性的。

⛔⛔ **混音总长必须 > 成片总长。** `final_pass` 用 `-stream_loop -1` 垫 BGM，
短了会绕回开头——真发生过：旧混音 1341.5 s、成片 1355.1 s，最后 13.6 秒绕回开头，
而片尾出处卡正好从 1341 s 开始，听上去像「片尾特意放了开场曲」。**那是长度差出来的巧合。**

### 拼接：先剪掉渐弱的头尾再交叉

⛔ 史诗曲十有八九是**渐弱收尾**，前面也常有十几秒铺垫。两首这样的接在一起，
3 秒交叉正好落在两条尾巴中间——实测接缝处 200–2k 能量掉到 7~10 dB（比中位低 14~17 dB），
听上去就是「音乐没了」。

`_trim_quiet()`：进交叉之前先把**头尾比自身中位低 6 dB 的部分剪掉**，尾巴多留 3 秒给交叉用。

每首进片前先 `highpass=90(2阶)` + `150 Hz −7 dB 搁架` + `loudnorm I=-16`，再 3 秒 `acrossfade`。

## 成片混音链（final_pass.audio_graph）

```
人声 ─ 85Hz×2 高通 ─ 130Hz −1 ─ [陷波] ─ 1.5k +2.5 ─ 3.2k +2.5 ─ 增益 ─ 限幅 ─ 延迟 ─┬─→ amix
                                                                                  └─ apad ─→ 侧链
BGM  ─ 100Hz 高通 ─ dynaudnorm ─ 音量 ─ 淡入 ─ 裁到总长 ─ 淡出 ─ sidechaincompress ────→ amix
                                                                          amix(longest) ─ alimiter
```

### 侧链闪避

⛔ **深度要量**：`ratio=7 + level_sc=3` 实测压了 **22.3 dB**——那不是闪避，
是「人声一来 BGM 消失、一停又蹦回来」，抽吸感很重。
定版 `threshold=0.030 / ratio=2.6 / attack=18 / release=420 / level_sc=1`，实测约 **9 dB**。

压干净之后 BGM 反而能整体提高：「宏大」听得见，糊却没有了。

⛔⛔ **侧链那一路必须 `apad`。** `sidechaincompress` 走 framesync，
**两路里短的那路一结束它就收工**——侧链就是人声，人声一完它就停，
BGM 在进 amix 之前已经被截断，只改 amix 的 duration 根本没用（实测改成 longest 后音轨长度一秒没变）。

### BGM 的动态

⛔ 「有部分片段 BGM 声音很小」量出来是**曲子自己的弱段被原样带进来了**：
19 分钟的混音里短时电平极差 **25.8 dB**，有一段掉到比中位低 22 dB = 等于没声。
选曲和拼接都不背这个锅，是史诗管弦本身的动态。

`dynaudnorm=f=500:g=31:p=0.75:m=6:r=0.0:s=12`（500 ms 帧 + 31 帧高斯窗 = 有人慢慢推推子）：
极差 **25.8 → 14.3 dB**，最轻的那段抬了 12 dB，峰值 0.73 不炸。
⛔ 别用 `acompressor`：`threshold=-24/ratio=3` 那档峰值直接顶到 1.000。
⛔ 上了 dynaudnorm 中位会被抬 2 dB 上下，`bgm_v` 要相应回收一档。

### ⛔⛔ 「呜呜」和「嗡嗡」是两种东西

这条查了三轮才查对，前两轮的归因都是错的。

| 症状 | 是什么 | 在哪 | 修法 |
|---|---|---|---|
| 呜呜（宽带低频隆隆） | ① BGM 的次低频 ② 人声自己的段落性隆隆 | 30–120 Hz | BGM 两道高通；人声支路串两级 85 Hz 二阶 |
| **嗡嗡（窄带稳态哨音）** | **TTS 在长段落上自己生出来的** | ~299 Hz，凸出邻域 **+12 dB**，出现在 **75%** 的人声间隙 | 真陷波 |

哨音的关键线索：**跟段落长度正相关**——长段 +12~+17 dB，短段只有 +2~+5，
而克隆参考音本身是干净的（+1.6）。**85 Hz 高通和 130 Hz 的 EQ 全都在它下面，一点碰不到它。**

定深度要拿「本来就干净的样本」当标尺：有声帧 250–350 Hz 相对 1–3 kHz，
参考音 +5.67、干净段 +2.60；最脏的段 +7.95 → 陷波后 **+1.21** 落回标尺附近，
再狠到 −24 就掉到 −3.44 = 开始挖人声了。

工具选型走了三轮：

1. peaking EQ（`equalizer`）**打不死它**：标称 −18 dB，实测凸出只从 +18 降到 +8。
   因为它不是单一频点——陷掉 299 之后残留峰跑到 302~305，摊在一小片上
2. `afftdn`（自适应降噪）**完全无效**：+18.3 → +19.2。它把纯音当信号，那是对付宽带底噪的
3. **定版 = 真陷波 `bandreject`，两个中心各来两刀**：+18.3 → +2.8，语音带只损失 0.6 dB。
   比「单中心加宽三刀」对 250–350 更温柔（−0.68 vs −1.07），压制力一样

⛔ 上了陷波就**别再叠宽带衰减**：陷波已经从 250–350 取走约 3 dB，再叠一道就真把声音挖薄了。
⛔ 频点**量出来才填**（`config.audio.notch`），别照抄。不同 TTS / 不同参考音，位置不一样。

## 响度与真峰

**⛔⛔ 这是两个独立的验收项。**

| 项 | 目标 | 怎么量 |
|---|---|---|
| 响度 | `target_lufs`（默认 −11.5） | `ebur128` 的 `I:` |
| **真峰** | **≤ −0.3 dBFS** | `ebur128=peak=true` 的 `Peak:` |

限幅收到 0.98 时实测成片真峰 **+0.7 dBFS——已经削顶了**：
采样峰被挡住了，但 AAC 编码后的**峰间**真峰照样冲过 0。往下收的实测台阶：

| limit | 真峰 |
|---|---|
| 0.93 | −0.4（只富余 0.1，全片素材更多会顶过去） |
| 0.90 | −0.2（响度提到 −12.6 LUFS 之后峰更密，仍不够） |
| **0.88** | **−0.8** ← 定版 |

限幅只削峰不改响度，LUFS 基本不动，代价可以忽略。**每提一档响度都要重量一次真峰。**

### ⛔⛔ 「人声不够大」先量再改

量法：同一段渲「只有人声」和「人声 + BGM」两条，按 400 ms 一帧比。
实测**说话的帧上 BGM 加了 0.00 dB**（三个采样点都是）——侧链闪避早把 BGM 在人声底下压干净了，
所以问题是**绝对响度**，不是被盖。

该动的是 `target_lufs`，**不是去压 BGM**。而且 BGM 可以**同时**往上抬——
它只影响人声间隙，也就是「气势」本身。实测 −12.5 → −11.5 LUFS 的同时 BGM 0.26 → 0.34，
人声间隙的 30–120 Hz 反而从 +2.5 降到 +2.1 dB。

## 片尾不要配音 ≠ 片尾不要声音

⛔⛔ `amix` 的 `duration` 必须是 **`longest`**，不是 `first`。
`first` = 第一路输入（人声），人声在正片结束那一刻就没了，整条混音跟着断在那里——
**片尾十几秒的出处卡是死寂的**。

⛔ 这个坑**看代码推不出来**：按 `-t total` 推理会得出「片尾有 BGM」，实测 ffprobe 才发现音频流短了一截。
**音轨长度一律 ffprobe 量，别读代码。**

片尾段本身怎么做：整段**退出 SCENES**（写成 `scenes.TAIL_CARDS` / `TAIL_DUR`），
由 `final_pass.tail()` 拼成无声视频接在正片后面。
为什么不是「把最后一段的 narration 清空」：SCENES 里的段一定会被 TTS 走一遍，
narration 空了 `durs` 会记成 missing、align 的闸门直接挂。

## 只改音频的快路

```bash
python final_pass.py final     # 画面没变：封面 + 字幕 + 电平 + BGM 一次编码，≈1 分钟
BGM_V=0.28 python final_pass.py remix   # 只换音频：视频流 copy，十几秒
```

改了画面（clip/concat）才需要 `chain.py post` 那条慢链。

## 成片上的音频复核

- 逐分钟 RMS：中位附近，**没有任何一分钟比中位低 6 dB**（`verify.py` 第 ⑥ 条）
- 最后 8 秒 RMS > −45 dB（片尾不是死寂）
- 音频流时长 ≈ 视频时长（差 <0.35 s）
