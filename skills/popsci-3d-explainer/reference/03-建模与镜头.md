# 03 · 建模与镜头

## 一镜的骨架

```python
def S11(out, preview):
    """一句话说清这一镜在演什么。"""
    B = _b("S11a", 270)                       # 拍点：N 和每个字的时刻
    sc = bs.reset_dark(preview)               # preview=True 关光追和阴影
    bs.lights(); bs.floor(-0.3, 120)
    obj = bs.某个零件(...)                     # 主角
    cam = L.camera(...)                       # 起手机位
    push(cam, B, a, b, target)                # 一镜只推一次
    L.label("t", "标签文字", loc, cam, appear=B.f("关键词"))
    _go(sc, out, B)                           # fit → relight → autoexpose → 字色 → 渲
```

`preview=True`：关掉 raytracing 和 shadows，**一镜 18 秒**；开着要 6 分钟。

## ⛔⛔ 四件事一律「渲一张小图量出来」

第一版每镜手写 `bs.lights(460, 190, 900)` 这样的常数，而场景尺度从 13 到 400 差三十倍、
相机又被自动取景退到任意远——**全片抽 125 帧实测平均亮度中位只有 0.088，亮于中灰的像素只占 2.9%**。
用户原话：「光线很暗，所有建模并不能完整照亮」。

`bs.go()` 一条龙做四件：

### ① 取景 `fit()`

- **只按 MESH 算**（`kinds=("MESH",)`）。第一版把标签也算进取景，一个标签飘出去就逼着相机退一大截，
  51/84 镜主体只占画面高不到 60%——「为了完整展示导致建模离得太远了看不清楚」。
  标签改成自己挪进画面（`_fit_labels`）。
- 只算**重心落在画内**的物体。横移镜头里还没走到的那一站本来就该在画外。
- 会**推近**也会后退；`_reaim()` 逐个相机关键帧把内容重心转到画面 (0.5, **0.57**)——
  略高于正中，把底部 22% 让给字幕带。
- ⛔⛔ **改完朝向必须当场打关键帧**。相机旋转是 orbit/key_cam 烤出来的曲线，
  下一轮 `frame_set` 会按曲线重新求值，不落关键帧这一步修正立刻被冲掉
  （调半天画面纹丝不动就是这个）。

**⛔ 没出场的东西要 `L.hide` 掉。** 吊在天上等着落位的楼、停在画外的图纸都算在外接框里，
相机只能一路退（实测主体只占画面高一成半）。但**起手也不能全 hide**：第一帧全黑会被空场检查报，
底座和头两层第 1 帧就该摆着。

**⭐ 天上有没有地方挂字，是能算出来的。** 取景按 MESH 框的**宽度**定，
16:9 下竖向只覆盖 **框宽 × 9/16**。用「框宽 × 9/16 − 主体高」先算一遍，
**不够 2 个单位就别往天上挂**——挂多高都会被排版工序拉回来压在主体上。

### ② 布光 `relight()`

删掉原有灯，按内容包围球半径 R 在**相机坐标系**里放 key / fill / rim / top，能量 ∝ d²（照度与距离无关）。

⛔ 主光要抬到接近顶光。压平了它在地板上的镜像会变成一大团白光斑，比主体还亮。
⛔ `relight()` 会**删掉所有灯重建**，镜头里自己给灯打的关键帧会被抹掉。
   要在某一帧调暗全场用 `bs.opts(dim=(帧, 倍数, 过渡帧数))`，它在重建之后统一打关键帧。

地板是近黑漫反射（底色 0.006、rough 0.88、metallic 0），世界背景压到同量级，
否则远处会出现一条明显亮过地板的地平线。`_stretch_floor` 按相机距离把地板拉到画外。

### ③ 曝光 `autoexpose()`

藏掉地板渲 320×180 小图，把主体像素的 p75 打到 0.44。

⛔⛔ **不能只量「比背景亮的像素」——那量到的是自发光。**
`m = g[g > bgv + 0.06]`（线性 0.06 ≈ 显示 0.29）在有发光件的镜头里只框到发光缝、标签、亮台子，
靠灯照亮的机身根本进不了掩膜。于是曝光判「够了」，旁边的东西黑成一片。

修法：再量一次**建模自己的画面框内**的 p75，两个取小的那个。

⛔ 这里有个二段坑：第一版用**整体大框**，遇到「一根斜放的长条 + 一颗小方块」时，
整体框占了大半张画面、框里绝大多数是空的，量出来就是背景电平——曝光一路推到 **×42，整幅纯白**。
改成 `_content_mask()`：**每个 MESH 物体各自的画面框**画进一张 mask，贴身得多。
再加一道收尾：循环结束后重新探一次，过曝面积压不到 6% 以下就一路往回收。

⛔ 主体掩膜不能用固定阈值——背景显示值约 0.11，写 0.05 会把整幅背景算成主体。
   先按 20 分位估背景电平再抠。
⛔ AgX 高光肩部很平，步长要取 `(target/cur)**1.9`，否则要跑七八轮。
⛔ 缩放要**连 `key_emit` 打过的关键帧一起缩**；曝光之后再新建的材质（字色、描边）要乘 `_EXPO["k"]`。
⛔⛔ **自动曝光会把标签的发光一起缩小**（标签也是发光材质，被缩到 0.26 倍，灰扑扑压在画面上）。
   标签是 UI，不能跟着场景调暗：`_scale_emission(k, skip=_font_mats(sc))`。

| | 修前 | 修后 |
|---|---|---|
| 某镜全帧平均亮度 | 0.045 | **0.185** |
| 同批镜头平均亮度中位 | 0.158 | **0.272** |
| 高光 p95 中位 | 0.340 | **0.530** |
| 曝光系数最极端 | ×42.01（纯白） | **×2.01** |

### ④ 字色 `fix_text_pixels()`

把字全藏起来渲一张小图，直接量每个标签**将要落在的那块画面**多亮。

⛔ 第一版用射线往字背后打、判那个物体的材质亮度——**判错了**：
四个青字压在发白的亮台子上，射线穿过去打到的是暗地板，判成「没问题」，实拍一个字看不见。

⛔⛔ **「底子亮就换深字」这条会做出空心字。** 相机一路在推近，标签背后那块画面一直在变，
单次判定必然不准；判成深字再配白描边，看起来就是镂空的。
**默认走「亮字 + 深描边」**这个标准做法，只有底子**确实很亮而且匀**才换深字：

```
bg > 0.72  且  sd < 0.13      ← 两个条件都要
```

- 门槛从 0.62 抬到 0.72：有句子压在一排会亮起来的石碑顶边上，中位数被那条白边拉过 0.62，
  可字大部分落在黑背景上——渲出来是一行灰字加白描边。
- 判亮度用**中位数**不用 70 分位：p70 会被少量高光带偏（句子压在「暗芯片 + 金色网格」上时，
  p70 落在金线上就判成底子亮）。
- 明暗混杂的（patch 标准差 ≥0.14）再加一圈**反色描边**。⛔ 膨胀量要小，0.05 会把中文笔画糊成一团白块。

改完之后全片深字从 58 条降到 4 条。

## ⛔⛔ 排标签是一条有顺序的流水线，谁在最后谁说了算

某一版 85 镜里 6 处出问题（三条标签叠成一行乱码、两条压着、一条挂在画外），
**联络表缩到 1/6 一条都看不出来**，是把 1080p 原图调出来才发现的。病因有六层：

| 病 | 病因 | 修法 |
|---|---|---|
| 两条摞成一条 | `_lift_labels` 把每条越界标签的**下沿都顶到同一个 y** | 顶完必须再推开一次 |
| 推开了又叠回去 | 推开之后相机又动、字号又改，屏幕位置全变 | **相机先定死**，之后只许平移不许改字号 |
| 画外的没人管 | 判据写了「已经在画面下方外面就跳过」 | 规矩只有一条：字幕带上沿以下不许有标签，**画外的更要捞回来** |
| 被放成 120% 画幅宽 | 「缩」和「放大」写在同一个 dict 里互相覆盖 | 分开收：`cap`=各帧能塞进画面的上限（取最小），`want`=最小那帧的可读下限；**want 先取、再被 cap 压住** |
| 推四轮还差 2% | 几帧的位移**相加**了，推过头再往回推 | 取需求最大的那一帧，且用**那一帧**的相机基向量换算 |
| 死活分不开 | 按**当前缩放**量框——标签是 `pop()` 弹出来的，弹出那几帧框比真身小一圈 | `_nbox()` 一律按满尺寸量 |

收敛写法（`fit()` 尾部）：

```
相机定死 → _fit_labels()            # 允许改一次字号
for _ in range(6):
    n  = _fit_labels(resize=False)  # 只平移
    n += _lift_labels()             # 让开字幕带
    n += _spread_labels()           # 推开重叠
    if not n: break
_label_audit()
```

三件**都往上推**，不会互相抵消（旧版「一个往下一个往上」必然原地踏步）。
上下都顶死时打印 `LABEL_STUCK`，那是只能改布局的。

⭐ `_label_audit()` 每镜七帧逐帧量，出界 / 相压各报一条进渲染日志，`chain.render` 原样带出来。
**渲完 `grep LABEL_` 就知道还有哪几镜要手改。**

配套两条：
- 字号写死在世界坐标里而相机距离是解出来的，同一个 `size=0.5` 在 26 单位外只剩十来像素。
  `_fit_labels` 有下限：在屏高度不足 **2.6%**（1080p 约 28 px）就放大，最多 2.4 倍。
- 排标签的四道工序必须看**同一组帧**（`LPROBE`）。各看各的，体检就会在别人没看过的那一帧上报错，
  而且永远修不掉。

## ⛔ 「内容比画幅还扁」只能改布局，改相机没用

`qc_shot.py` 的 `cshape` = 主体自身宽高比 ÷ 16:9。
**>1.7 说明内容本身比画幅还扁**，这时相机怎么调主体都高不起来。85 镜里有 16 镜中招。

两种修法：

- **斜着看这条线**：顺着长轴斜过去，透视一压就够了，不动建模
- **前后错开**：排成斜线 + 斜机位，一条直线变成有纵深的斜构图

⛔ `bs.opts(oblique=False)` 关掉自动斜看——**左右并排对比的镜头一转就把并排看成前后**。

## 几条具体的坑

- ⛔ **`L.key_loc` 会就地修改 `o.location`**：先写「抬高 5」再拿 `tuple(o.location)` 当落点，
  读到的已经是抬高后的值，整摞永远不落地。**落点必须先存下来。**
- ⛔ `bs.stack()` 的返回值**只有芯片层**，层间发光缝和 base 不在里面——楼落了缝留在半空。
  要按名字前缀收齐整摊。
- ⛔ `key_rel` 而不是 `L.key_scale`：`L.box` 把 size 存进 `object.scale`，
  直接 `key_scale(o, f, (1,1,1))` 等于把它压成 1×1×1。
- ⛔ **发光件别超过 emit 2**：内存条上高亮的那颗芯片 emit 2.0 会烧成纯白块，改 0.9。
- ⛔ **底色不能太黑**：第一版材质基色在 0.05 以下，靠布光救不回来，全片像没开灯。
  现在芯片 0.10、硅 0.10、PCB 0.05/0.16/0.10。
- ⛔ **俯拍镜头不能用 `face_cam`**：相机几乎正对下方时 TRACK_TO 的滚转不稳，字会倒过来。俯拍用 `flat_text` 平躺。
- ⛔ **一镜的字有行数上限**。实测某镜只能挂两行：挂三行时第三条被排版工序顶到第二条上面，两条叠在一起。
- ⛔ **字不能放在主体下方**：`_lift_labels` 会把落进字幕区的标签抬回来，正好压在主体身上。
  所有字一律放在主体上方的黑场里（前提是天上算得出空间，见 ①）。
- ⛔ `L._font` 是模块级缓存，`read_factory_settings` 之后会失效，每镜要置 None。

## 转场：溶解但一帧不改时长

⛔ 不能直接上 `xfade`：它会把总时长缩掉 (n−1)×T，而字幕和拍点都按 align 的**绝对秒**排。

做法是每段多取 `shot_xfade` 秒素材，再用同样长的 xfade 叠回去：

```
总长 = Σ(dᵢ+T) − (N−1)·T = Σdᵢ      每个切点仍落在原来那一帧
```

镜与镜之间 0.26 秒，段与段之间由 `transition=0.3` 负责（`subs.py` 已经按它扣过接缝）。
加上取景统一把主体放在画面同一位置，相邻镜头就有了「同一个东西在演变」的感觉。

## 渲染

```bash
python chain.py render              # 全量
python chain.py render S11,S12      # 只重渲这几镜
python redo.py S03,S05              # 先把旧帧搬走再渲（chain 看 done.txt 会跳过）
python run_par.py S01,S02,...       # 并行：一个进程一份互不相交的清单
```

- ⛔⛔ **开渲前必须量盘**：一部片 32 GB，每重渲一轮多压 30 GB 废弃帧。
  盘满时 blender 每帧报 `No space left on device` 而**完成计数一直不涨**，光看日志会以为只是渲得慢。
  monitor 除了盯计数，要再 grep 一条 `No space left`。
- ⛔ 看门狗按**帧文件的 mtime** 判，不是按计数——一个 400 帧的镜头能渲 20 分钟。
- ⛔ **别在重渲途中改生成器**：改一次，前面已经渲完的那些镜头就停留在旧逻辑上。
- ⛔ 废弃帧**只搬不删**（`redo.py` / `run_par.py` 已经这么做），每批一个日期目录。
  查回归时要拿旧帧和新帧对照——「这处压字是不是这轮弄坏的」只能这么判。
  跨盘搬 PNG 序列是小文件海，实测机械盘只有 55 MB/s，119 GB 要 36 分钟，别在开渲前一刻才清。
- ⭐ 并行吞吐：2 进程 **1.60×**、3 进程 **1.81×**（边际很薄）。瓶颈是同步延迟不是算力
  （GPU 利用率 73% 但功耗只有 125W/310W）。⛔ 单次 `nvidia-smi` 采样不可信。
- ⛔⛔ 多进程渲染时，所有写 `%TEMP%` 的临时文件名**必须带 PID**。
  三个 blender 抢同一个曝光探针 PNG 时，某一镜会 **4 秒 FAIL 且没有任何 traceback**。
