# 02 · 配音与对齐（声音决定时间轴）

## 链路

```
scenes.py
   └─ make.py storyboard  ──→  storyboard.json        ← ⛔ 改稿后第一件事
        └─ chain.py tts   ──→  work/film/tts/*.wav
             └─ chain.py audio
                  ① tts → tts_raw（只在缺文件时建立，之后**只读**）
                  ② make.py voice：tts_raw → tts（去次低频 → 电平骑行 → 对齐 LUFS → 限幅）
                  ③ align.py：第一遍逐字对齐（拿到插停顿要用的字边界）
                  ④ pauses.apply()：在转折处开口子
                  ⑤ make.py durs：量时长（必须在插完停顿之后）
                  ⑥ align.py：**全量重对齐**
                  ⑦ make.py storyboard：把切点 t 写进去
                  ⑧ make.py beats  ──→  beats.json   ← 渲染的时间来源
```

---

## ⛔⛔ 改过稿必须先刷 storyboard 再对齐

`chain.audio()` 内部的顺序（对齐 → 插停顿 → 重对齐 → 出 storyboard）**只对「稿没动、只重配音」成立**。
改了稿还照这个顺序跑会这样炸：

1. `align.py` 的文本来自 `storyboard.json`——那里面还是**旧稿**
2. 于是 `align.json` 里存的 `disp` 是旧稿
3. `make.py storyboard` 重建时一比 `disp != a["disp"]`，打印「align 过期」然后**整段跳过**，所有块都没有 `t`
4. `make.py beats` 到这儿直接 `KeyError: 't'`

**正确做法：改稿之后第一件事是 `python make.py storyboard`**（这一轮的「align 过期」是预期内的），
然后才跑 `chain.py tts` / `chain.py audio`。

---

## tts_raw 是原始素材，只读

```python
if not os.path.exists(dst):
    shutil.copy2(f, dst)          # ⛔⛔ 不能按 mtime 同步
```

`pauses.apply()` 会**就地改** `tts/`。按 mtime 同步的话，第二次跑 `audio()` 时
「已插过停顿」的音频会被当成原始素材抄进 `tts_raw`，原始输出就永远没了。

`make.py voice()` 每轮都从 `tts_raw` 重建，所以**停顿每轮都要重插**——这是设计，不是重复劳动。

---

## 三件不改音色的处理（make.py voice）

用户听后期链觉得「嗡嗡」之后定的：**不上压缩器、不做染色 EQ**，只做三件。

| # | 做什么 | 为什么 |
|---|---|---|
| ① | 70 Hz 二阶高通 | 人声基频最低也在 85 Hz 以上，这一刀只去隆隆声 |
| ② | **段内电平骑行** `_level_ride` | 「声音忽大忽小」实测段内 3 秒短时电平极差 **13.4 dB**，逐段静态增益完全盖不住 |
| ③ | 对齐到 `seg_lufs` + 限幅 | 各段响度差 2~5 dB |

**电平骑行不是压缩器**：算一条 1.6 秒窗口的响度包络，取倒数当增益曲线，
再把曲线平滑到「每 100 ms 最多动 0.35 dB」——听感上等于有人在旁边推推子，音色一点不动。
静音段的增益冻结在前一个有声值上，免得把底噪抬起来。

实测：段内极差 13.4 → **2.7 dB**，全片 p5~p95 跨度 1.2 dB。

## 插停顿：为什么要在波形上开口子

实测 TTS **不按标点改停顿长度**——转折处 0.00~0.23 秒，和同段普通停顿（中位 0.16 秒）没区别。
`{{，|。}}` 这类改读音的写法**量不出任何效果**。所以只能在波形上开口子。

### 三条（都是「吞音」反馈之后定的）

第一版按 align 的字边界中点直接下刀，而 whisper 的字边界有 ±100 ms 误差，
实测 **33/33 处全部切在有声处**（切口两侧 −13~−25 dB）——等于把每个转折点前那个字的尾巴齐根削掉。

| # | 规矩 |
|---|---|
| ① | 刀口只落在**能量谷底**：在目标时间 ±150 ms 里找最安静的 10 ms 窗口 |
| ② | 按「**目标间隙**」补足，不是硬插。本来就有 0.18 s 的缝就只补到 0.52 s，否则转折处会变成一秒多的大坑 |
| ③ | 切口**两侧**各 12 ms 余弦淡入淡出。第一版只给末段做了淡入，于是每处停顿**之后**那一刀都是硬起，21/65 处的后侧还在 −17~−30 dB = 削掉了下一个字的字头 |

静音块**不铺数字零**，铺「切口附近最安静那 20 ms 的环境底噪」×0.55——纯零会让人听出「断了一下」。

### 闸门 `pauses.py check`

判据换过三次，前两次都是错的：

1. 找「数字零」段——静音块铺的是底噪，根本找不到 ✗
2. 量紧挨着的 20 ms ≤ −38 dB——插完两侧有淡入淡出，那儿必然是渐变，苛求 ✗
3. 量离切口 60 ms 外的电平——把 TTS 自带的 287 处自然停顿全算进来了，96 处「不合格」其实是正常连读 ✗

**现在的判据：刀口那 40 ms 的电平要比它周围 ±250 ms 的语音电平低 12 dB 以上。**
低得不够 = 这一刀砍在一个字的中间。只查**我们自己插的**那几十刀。

### ⛔⛔ 落点失效是静默的

落点串是显示文本里的唯一子串。句子被改掉、或者段被拆开之后，`plan()` 只打印一行
「!! pXX 找不到落点」，日志一长根本看不见——真发生过：一段拆成三段后，四个落点还挂在原段名下，
**新段整段一处停顿都没插过**，一直到成片才被听出来「这段没有呼吸」。

**改完稿一定要跑 `python pauses.py plan`，逐行看有没有「找不到落点 / 落点不唯一」。**

## 逐字对齐（align.py）

whisper 的词级时间戳 → 每段口播每个「显示字」的 (起, 止) 秒。
比对用**读音侧**文本 vs whisper 文本做 difflib，未匹配段按线性插值。

### ⛔⛔ `condition_on_previous_text` 必须关掉

它默认 True，会让 whisper 在长音频上**解码循环**——实测一段 126 秒的音频，
转写里同一句话连着出现了 6 次，而同一个文件单独重转一遍是干净的、切成几秒的短片段也是干净的：
**音频没问题，是解码跑飞了**。

后果不是听感，是 `check_dup` 拿这份转写当证据、报了假的「整段复读」，
差一点去切一段本来好好的音频。

（逐字时间戳这一路没被带坏——实测全部单调、无停滞、覆盖 99~100%。）

### 对齐产物的验收

`chain.audio()` 跑完会逐段查三条，任一不过就 assert：

- 文本对得上（`disp` == 去覆盖后的口播）
- 时间戳条数 == 显示字数
- 末字的止 离 wav 结尾 < 2.0 秒

⛔ `align.py` 跑完会在退出阶段崩（faster-whisper teardown，0xC0000409），
但 `align.json` 已经写完了。**所以不看退出码，只看产物。**

## 拍点（beats.json）

```python
{"S11a": {"N": 283, "dur": 8.93, "text": "这一块的口播原文", "t": [[0.15,0.31], ...], "scene": "p03"}}
```

- `N` = 这一镜要渲多少帧 = (块时长 + 0.5 秒) × fps
- `t` = 每个显示字相对**块首**的 (起, 止) 秒

镜头里怎么用：

```python
B = L.beats("S11a", 270)
f = B.f("混合键合")        # 这个词开口的帧号（已提前 4 帧）
g = B.end("混合键合")      # 说完的帧号
h = B.frac(0.55)           # 兜底：按比例取
L.render(sc, out, 1, B.N)
```

⛔⛔ `B.f()` 找不到词只会**静默退回默认帧**。`check_beats_kw.py` 就是专门堵这个的：
把每个镜头函数体里的 `B.f("…")` 逐个和那一块的口播比，一个不命中就 FAIL。

⛔ **拍点别打在整块的最后三个字上**。实测打在口播 94% / 96% 处的两个标签，
露脸不到一秒。打在短语开头：动作先发生，名字随后落。

## 两道回读检查

| 工具 | 抓什么 | 判据 |
|---|---|---|
| `check_read.py` | 多音字读错 | 把 whisper 听到的**读音**和让 TTS 读的**读音**逐音节比 |
| `check_dup.py` | **整段复读 / 整段吞掉** | 拼音序列里任何 ≥8 音节的 insert 或 delete |

⛔⛔ **两个都要跑。** `check_read.py` 只报 difflib 的 `replace` 且限制 ≤3 个音节——
几十音节的整段复读是一个 `insert`，它一条都不报，给的还是 `READ_OK`。
真事故：一段 500 字的口播从第 19 秒起把开头 19 秒原样又念了一遍，
字幕因此有一条挂了 20.26 秒（whisper 把稿子的字对到第一遍上，下一句的时间戳落在复读之后）。

⛔ `check_read` 不做模糊匹配（把 zh/z、ch/c、in/ing 当同音）——真抓到的那次读错
正是 cheng2/ceng2 这一对，糊掉就再也抓不到了。宁可逐条白名单。

⛔ `check_dup` 两边都要先去掉中文数字字符——whisper 把「百分之八十七」写成「87%」，
只留汉字的口径会把稿子那边的中文数字整串当成「吞掉了」，一跑一堆假警报。

### 复读了怎么修

在 **tts_raw**（原始素材，不是 `tts/`）上切掉重复段，刀口在两个边界各自 ±0.30 秒里找最安静的 20 毫秒，
15 毫秒交叉淡接。**连锁反应要算清楚**：段变短 → 全量重对齐 → 拍点变 →
**帧数对不上的镜头全部重渲**（不只是这一段的那几镜，whisper 重对齐会让其他段也有几帧位移）。
判据必须是「帧数**恰好相等**」，见 `07-坑册.md`。
