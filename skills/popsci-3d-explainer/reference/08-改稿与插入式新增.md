# 08 · 改稿与插入式新增

用户看完片子提意见，是这条线上**最频繁**的动作。处理方式决定了这一轮要花 10 分钟还是 4 小时。

---

## ⭐⭐ 首选：插入式新增，不改旧段

要补一段内容（解释一个名词、加一条新消息、回收前面的伏笔）时，
**新开一段 `P("p09d", [...])` 插在两段中间，旧段的口播一个字不动。**

好处：旧段的 **wav / 对齐 / 帧数 / 画层的章全部原样有效**，只有新段要渲。

```python
SCENES = [
    ...
    P("p09c", [...]),      # 旧段，不动
    P("p09d", [            # ← 新段插在这儿
        ("前面留了一个问题没回答……", {"seg": "S105a"}),
        ("这个新名词是什么？", {"seg": "S106a"}),
    ]),
    P("p10", [...]),       # 旧段，不动
]
```

配套要改的四处（**一处都不能漏**）：

1. `chapters.py` 的 `CH` 和 `SEC` —— 漏了会在 `final_pass` 最后一步 KeyError
2. `pauses_table.py` —— 新段的停顿落点
3. `config.json` 的 `shot_files` —— 如果新镜写进了新文件
4. `verify.py` 的自定义条目 —— 新内容该出现的词

⚠️ **实际上仍然会重渲一部分镜头**：重跑全量对齐后 whisper 的逐字时间有 1~16 帧抖动，
帧数和 beats 对不上的镜一律重渲，不留「章和帧对不上」的格子。
但那是几十镜，不是全部。

## 改旧段的连锁反应表

| 改了什么 | 连锁 |
|---|---|
| 某段的一个字 | 那段重配音 → 重插停顿 → **全量重对齐** → 拍点变 → 帧数不符的镜头全部重渲 |
| 只改读音侧 `{{长\|涨}}` | 显示串没变但 wav 变了 → **仍然要重对齐**，否则字幕整段错位 |
| 拆段 / 并段 | 上面全部 + 章节表 + 停顿落点表 + 配音段数 assert |
| 某一镜的建模 | 只有那一镜重渲；但**画层指纹变了**，那一格的章自动失效 |
| `bl_scene.py` / `bl_lib.py` | **所有建模镜的画层章全部失效**（指纹含这两个文件） |
| 卡片样式 | 所有含卡片的段的画层章失效 |
| 字幕样式 / BGM 音量 / 响度 | 只跑 `final_pass.py final`（≈1 分钟）或 `remix`（≈15 秒） |

**正确顺序**（改稿之后）：

```bash
python gen_gao.py                 # ① 稿跟着分镜走
python check_scenes.py            # ② 逐字比对，CHECK_OK 才往下
python make.py storyboard         # ③⛔ 必须在对齐之前！
python chain.py tts p09d          # ④ 只配改动的段
python chain.py audio             # ⑤ 全量：插停顿 → 重对齐 → 出 beats
python pauses.py plan             # ⑥⛔ 逐行看有没有「找不到落点」
python check_beats_kw.py          # ⑦ 拍点词命中
python chain.py render            # ⑧ 只有帧数不符的会真渲
python chain.py post
python grid.py && python verify.py
```

## 帧序列已清、还要删段：在正片 mp4 上动刀

场景：片子交付后帧序列已经清掉了（一部片几十 GB），又要删掉一整段或几句话
（比如某个平台限流、要把某段内容拿掉）。重配 + 全量重渲要几个小时，而**删除**其实不需要新画面。

前提：`成品` 之外还留着 `work/film/out/<片名>_成片.mp4`——**带人声、无字幕、无 BGM** 的正片。
字幕、BGM、片尾都是 `final_pass` 后加的，删完正片再跑一次 `final` 就全回来了。

**⭐ 原则：视频和音频各自找刀口，差额用冻帧补齐。**

1. **先还原旧时间轴。** 每段在正片里的起止，从旧 `subs.ass` 的 HUD 行反推（HUD 起点 = 段起点 + 固定偏移，章首段偏移不同），
   比 `_durs.json` 累加准；拿每段 tts wav 和正片音轨做互相关验一遍，误差应在 ±0.04 s。
2. **音频刀口按能量找。** 短时电平（20 ms 窗）低于 −40 dB 的连续区间才算静音，30 ms 以内的小凸起合并掉
   （停顿里插过的底噪会把静音区打碎）。刀口落在静音区里，**保留原来那个停顿的长度**。
   ⛔ 别用 whisper 字边界下刀，±100 ms 的误差会切掉字头字尾。⛔ 步长换算见 07 号「越往后越找不到」。
3. **视频刀口落在纯镜头里。** 避开镜间 0.26 s、段间 0.3 s 的溶解窗，否则会带出半透明的旧画面。
   要删的画面元素（字、标签）如果在镜头后半段才出现，刀口就提前到它出现之前。
4. **两边删掉的长度不同，差额用冻帧补**（实测 0.4~1.1 s，落在停顿里看不出）。
   取帧 + 补帧的 filter 串：`-ss … -t … -i 正片 -vf "select='between(n,a,b)',setpts=N/FRAME_RATE/TB,fps=30,tpad=stop_mode=clone:stop=N"`，
   ⛔ `fps=30` 不能省（见 07 号 tpad 那条）。
5. **画面里带要删内容的镜头**（一个标签、一根柱子）才重渲那一镜，时长按新时间轴算，冻帧对齐进去。
   要改口播的段（比如开场预告里提到了被删的内容）才重配那一段。
6. 旧秒 → 新秒的映射表同时用来：平移 `align.json` 的逐字时间（出新字幕）、给重渲镜头算拍点、放置新画面块。
   刀口两侧 0.35 s 内的字按最近的片段夹紧。
7. 章节表、停顿表、片尾出处卡跟着删；然后 `final_pass.py final` 出成片。

**验收额外两条（加进 verify）：**
- 字幕 / HUD / 片尾卡 grep 被删的关键词（包括它们的同音误写），0 命中；
- **whisper 把成片从头听一遍**，转写里 grep 同一组词，0 命中；再打印每个接缝前后一句的转写，逐条读通顺。
  只查字幕不够——字幕是按新时间轴生成的，查不出音频里残留的半句。

## 怎么接用户的意见

### ① 先分类：这是「画面改」还是「素材改」

| 类型 | 例子 | 代价 |
|---|---|---|
| 只动最后一次编码 | 字幕断句、BGM 曲单和音量、响度、水印、章节名 | **1 分钟** |
| 只动几镜 | 某个标签被切掉、某镜主体太小、字压在物体上 | 几分钟一镜 |
| 动素材层 | 改词、改读音、加内容 | 半小时~几小时 |

**能放进第一类的就别放进第三类。** 比如「有呜呜声」——修在成片混音上，不是回去改配音链。

### ② 用户的说法和事实冲突时

真发生过两次：
- 用户说「这一环的差距是**最小**的」，而卡片红框和出处写的是「这一环是短板」——正好相反
- 用户猜「已经不是靠便宜在卖了 = 质量良率跟上来了」，而出处原文明确否定了这个猜测

处理：**一次性把两条都问清楚**（别分两轮问），用户答「按照真实的来」之后按事实写，
并在交付说明里**把这一处点出来**（「你写的是 X，和画面/出处相反，问过你之后按事实写」）。

### ③ 有些意见的正确解法不是照做

| 用户说 | 直觉解法 | 实际解法 |
|---|---|---|
| 「混合键合」被读成「混合键 合」 | 加读音覆盖 | ❌ `{{}}` 只换读法，**断不断由韵律决定**。要**改句子结构**：把词挪到句末、前面加「这叫」 |
| 「台积电不是三大厂商之一，提一下它做什么」 | 塞进原来那句里 | ❌ 那一块只有 6 秒，塞 60 字会变成一个不动的特写。**加一块新镜** |
| 「人声再大一点」 | 压 BGM | ❌ 量出来说话帧上 BGM 加了 0.00 dB。**改的是绝对响度**，BGM 反而能同时抬 |
| 「中间比较平淡，BGM 换一下」 | 换曲子 | ⭕ 但先 `bgm.py prof` **量出来是哪几首、平在哪一分钟**，再换 |
| 「片尾那段 BGM 好听，放中间去」 | 调曲序 | ❌ 先查：那可能是 `-stream_loop` 绕回开头的**巧合** |

**共同点：主观说法先转成可测量的判据，量完再动手。** 量出来常常推翻直觉。
