# 06 · 验收与格子法

## 为什么要格子法

我（模型）**看不了动态画面、听不到声音**。所以验收分两半：

- **能量化的** → `verify.py` 十四条，全部落在成片上，每条给可复核的数字
- **只能人眼看的** → 三层格子，一格一格亲眼看过再盖章，章绑指纹，指纹一变章自动失效

⛔ 格子法开跑前问一句用户要不要用。用了就**逐格盖章、章绑指纹、不满意自己重跑、填满才交付**。

---

## 三层格子

```bash
python grid.py                                    # 看状态
python grid.py --过 稿:p01 --因 "看了什么"
python grid.py --过 画:S11,S12 --因 "亲眼看了这两镜的哪几帧"
python grid.py --退 画:S05 "电子看不见"
```

三层的**格子单位不一样**：

| 层 | 一格是 | 指纹 |
|---|---|---|
| 稿 | 一段 | md5(口播) |
| **画** | **一镜** | md5(该镜的分镜规格 + **生成器源码** + 渲出来的帧数) |
| 段 | 一段 | 稿指纹 + 该段所有镜的画指纹 + 配音 wav 的 md5 |

**判据只能是自己看画面、自己听声音**，不是看文件在不在。用 `look.py` 把镜头渲成 960×540 来看。

### ⛔⛔ 生成器指纹漏登 = 盖假章

「生成器源码」那一项哈希的是 `config.shot_files` + `bl_charts.py` + `bl_scene.py` + `bl_lib.py`。
**镜头函数每多拆出一个文件，就必须登进 `config.shot_files`。**
漏了会怎样：改了那个文件里的镜头、只要帧数没变，**旧的「过」章还原样生效**——
格子法的核心契约破了，而且一点提示都没有。这条栽过两次。

### ⛔ 沿用旧章要先证明帧没动过

重渲了一部分镜头之后，其余镜头沿用旧章是合理的——但要先用 **mtime** 证明
它们的帧文件在某个时间点之后没被动过，再说「沿用」。

## `verify.py` 十四条

```bash
python verify.py
```

| # | 查什么 | 判据 |
|---|---|---|
| ① | **成片是最新的** | 成片 mtime > 所有 done.txt / clips / bgm_mix / subs.ass |
| ② | 音视频等长 | ≥2 条流；音频时长与视频差 <0.35 s |
| ③ | 整片响度 | 与 `target_lufs` 差 ≤1.2 LUFS |
| ④ | 真峰不削顶 | TP ≤ −0.3 dBFS |
| ⑤ | 片尾有声音 | 最后 8 秒 RMS > −45 dB |
| ⑥ | 没有塌掉的分钟 | 逐分钟 RMS 都不低于中位 6 dB |
| ⑦ | 帧数对齐拍点 | 每镜 done.txt **恰好等于** beats 的 N |
| ⑧ | 两道渲染前闸门 | `CHECK_OK` + `KW_OK` |
| ⑨ | 自插停顿没吞音 | `PAUSE_CHECK_OK` |
| ⑩ | 字幕不超宽不倒标点 | 最长 ≤20 字、0 条以标点开头 |
| ⑪ | 章节条单调 | 章名 x 坐标单调不减 |
| ⑫ | 素材零复用 | 没有 seg / real 出现两次 |
| ⑬ | **BGM 听得见** | 人声间隙 RMS 的 p05 落在 −26…−20 dBFS（⑤ 只量片尾，测不到这个）|
| ⑭ | **读音覆盖表都生效了** | 表里的词在正文里没有一个是裸着的 |

⛔ ⑬⑭ 是 v4 补的两条，补的原因是**这两处当时全绿、用户一看一听就发现是错的**。
⑬ 的坑在 `05-混音与BGM.md`「片尾有声音证明不了 BGM 听得见」；
⑭ 的坑在 `01-文案与分镜.md`「表只证明没念丢，证明不了念得对」。

### ⛔⛔ 第 ① 条是最重要的一条

「A 生成 B、下游只读 B」的地方如果不加 mtime 闸门，量的就是**上一轮的产物**。
这条坑给过两轮假绿灯——看着全绿，其实验的是旧片。

**验收必须落在用户要打开的那个文件上。**

### 加自己的条目

每轮用户提的具体改动，都值得加一条「该出现的词都在、该删的都不在」的检查：

```python
need = ["这一轮新加的那句话", "改过读音的那个词"]
gone = ["这一轮删掉的那句话", "旧的错误说法"]
```

从成片的 `subs.ass` 或 `scenes.py` 里 grep。这样下一轮改动不会把上一轮的改回去。

## 画面的量化体检

| 工具 | 抓什么 | 怎么跑 |
|---|---|---|
| `preview_all.py` | 低清预览 + 空场检查 + 联络表 | `python preview_all.py` / `qc` / `sheet` |
| `qc_fit.py` | 不渲染，只投影：主体有多少落在画内、主体占画面高、标签出没出界 | `blender -b --python qc_fit.py -- all` |
| `qc_shot.py` | 逐镜渲 3 帧按像素量：取景 · 光 · 字色 | `blender -b --python qc_shot.py -- out.json S11,S12` |
| `qc_all.py` | 把 `qc_shot` 铺满所有镜，分批跑并成一张表 | `python qc_all.py` |
| `look.py` | 渲成 960×540 给**人眼**看 | `blender -b --python look.py -- outdir S70,S74` |

`qc_shot` 的指标：

| 指标 | 含义 | 红线 |
|---|---|---|
| `fillh` / `fillw` | 主体（只算 MESH）占画面高 / 宽 | 高 <0.33 = 主角太小 |
| `cshape` | fillw/fillh ÷ (16:9) | **>1.7 = 内容比画幅还扁，只能改布局** |
| `clip` | 主体落在画内的比例 | <0.98 = 出画 |
| `avg` / `p95` / `br` | 整帧平均亮度 / 95 分位 / 亮于中灰的像素占比 | |
| `subj` | 主体像素的平均亮度 | |
| `floorhot` | 地板是不是画面里最亮的东西 | 1 = 对比度塌了 |
| `txtmin` | 所有标签里笔画 vs 背景对比度最小的那个 | <0.18 = 浅底浅字 |

⛔ **这张表是筛子不是判据**：`txtmin` 只采 85% 那一帧，经常逮到正在弹出动画中途的标签，
把好镜头报成低对比；`clip` 也会把「出生点在画外」的粒子算成出画。
**排完序还是要一镜一镜看图。**

⛔ 分批（每批 12 镜）不是为了好看：一次性把 88 镜塞给一个 blender 进程，中途崩一次前面全白跑。

⛔⛔ 这些工具**不能写 `import bl_shots`**：别的片子目录里往往有同名文件，
而 `sys.path` 的顺序会被 `bl_scene` / `bl_shots` 自己的 insert 改好几道——
曾经因此把上一部片的 14 镜量了进来、把本片 35 镜全漏掉，**不报任何错**。
一律用 `shotload.py` 按绝对路径加载。

### 渲染日志里的 `LABEL_`

`_label_audit()` 每镜七帧逐帧量标签，出界 / 相压各报一条。`chain.render` 把这些行原样带出来。
**渲完 `grep LABEL_` 就知道还有哪几镜要手改。**

## 出片前的最后一道：拼联络表逐格看

⭐ 这是整条链上**最值钱的一次检查**。某一轮 45 镜渲完先拼联络表逐格看，
抓到**五处**字和字 / 字和物体叠在一起，补渲后才出最终片。

联络表缩到 1/6 时看不出标签细节——**发现「有东西压着」之后要调 1080p 原图确认**。

⚠️ 还要分清「本轮弄坏的」和「一直就这样的」：和回收站里的旧帧对照，
只修真回归。真发生过：五处里只有一处是本轮的回归，另外两处旧帧一模一样，没动。
